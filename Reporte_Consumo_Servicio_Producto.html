1. Introducción y Arquitectura
Marco Técnico

El presente informe documenta la implementación del flujo integral para el consumo de catálogos y registro de productos en la aplicación móvil institucional. La solución adopta un patrón MVVM (Model-View-ViewModel) estructurado sobre el framework React Native y Expo Router, asegurando desacoplamiento, robustez y mantenibilidad.

Endpoint y Servidor Backend
Servidor API REST alojado en https://api-ecommerce-5aby.onrender.com con protección por Bearer Tokens y endpoints: GET /categories (catálogo dinámico) y POST /products/create (creación de registro).

1.2 Flujo de Datos

1. Al renderizar el formulario, se verifica la autenticación del usuario y se ejecuta CategoryService.getCategories(token).
2. Al pulsar el selector de categoría, se activa el estado isCategoriesShowModal, renderizando un Modal nativo con FlatList.
3. Al seleccionar un elemento, se persiste su categoryId, se muestra el nombre seleccionado y se cierra el Modal.
4. El usuario completa los campos obligatorios (Nombre, SKU, Descripción, Precios y Stock).
5. Se invoca ProductService.createProduct(). Tras la respuesta del servidor, se imprime el objeto retornado vía console.log y se notifica al usuario con un diálogo Alert.alert nativo.

export function useCreateProduct() {
    const [categories, setCategories] = useState<CategoryResponse[]>([]);
    const [categoryId, setCategoryId] = useState<null | number>(null);
    const [isCategoriesShowModal, setIsCategoriesShowModal] = useState(false);

    // 1. Consumo del catálogo de categorías
    const fetchCategories = async () => {
        if (!token) return;
        try {
            setIsLoadingCategories(true);
            const data = await CategoryService.getCategories(token);
            setCategories(data);
        } finally {
            setIsLoadingCategories(false);
        }
    };

    // 2. Envío y registro del producto con console.log y alerta
    const submitProduct = async () => {
        if (!name.trim() || !sku.trim() || !description.trim() || !regularPrice.trim() || !initialStock.trim()) {
            Alert.alert("Error", "Por favor completa los campos obligatorios");
            return;
        }

        try {
            const createdProduct = await ProductService.createProduct({
                name: name.trim(),
                categoryId: Number(categoryId),
                sku: sku.trim(),
                description: description.trim(),
                regularPrice: parseFloat(regularPrice),
                offerPrice: offerPrice ? parseFloat(offerPrice) : undefined,
                initialStock: parseInt(initialStock, 10),
                minStockAlert: minStockAlert ? parseInt(minStockAlert, 10) : 0,
            }, token);

            // CONSOLE.LOG requerido para la rúbrica
            console.log(">>> [PRODUCTO CREADO EXITOSAMENTE EN API]:", JSON.stringify(createdProduct, null, 2));

            Alert.alert("Éxito", "Producto creado correctamente", [
                { text: "OK", onPress: () => router.replace("/(protected)/dashboard") }
            ]);
        } catch (error: any) {
            Alert.alert("Error", error.message || "Error al crear el producto");
        }
    };
}

6.2 Servicios de Comunicación HTTP (Axios)

// CategoryService: Consumo dinámico
export const CategoryService = {
    getCategories: async (token: string): Promise<CategoryResponse[]> => {
        const authToken = token.startsWith("Bearer ") ? token : ;
        const response = await axios.get<CategoryResponse[]>(, {
            headers: { Authorization: authToken }
        });
        return response.data;
    }
};

// ProductService: Creación e impresión del payload
export const ProductService = {
    createProduct: async (productRequest: CreateProductRequest, token: string): Promise<ProductResponse> => {
        const authToken = token.startsWith("Bearer ") ? token : ;
        const response = await axios.post<ProductResponse>(, productRequest, {
            headers: { Authorization: authToken, "Content-Type": "application/json" }
        });
        console.log("RESPUESTA_API_PRODUCT_SERVICE:", response.data);
        return response.data;
    }
};
7. Conclusiones
Evaluación Final

1. Separación de Responsabilidades: La implementación de la arquitectura MVVM permitió desacoplar la lógica del ciclo de vida de la red respecto a los componentes de presentación visual. La vista create-product.tsx se mantiene limpia y declarativa.

2. Carga Dinámica vs. Datos Estáticos: Se garantizó que el catálogo de categorías provenga 100% del servicio backend mediante CategoryService.getCategories, eliminando cualquier hardcoding y permitiendo que nuevas categorías registradas en la base de datos se reflejen en tiempo real en el Modal.

3. Experiencia de Usuario y Robustez: El uso de componentes nativos de diálogo (Alert.alert) provee una retroalimentación confiable e integrada con el sistema operativo anfitrión (Android / iOS), mientras que el registro mediante console.log permite trazabilidad inmediata para auditoría y depuración técnica.
